# 埋め込み・フロントエンドUX仕様書

## 1. Muse資産管理アプリへの `iframe` 埋め込み

### 基本スニペット（Muse側の実装コスト最小・単体完結）

```html
<iframe
  src="https://asoka501.github.io/Git_stock_networkmap/?embed=1"
  width="100%"
  height="600"
  style="border:0;border-radius:12px;"
  loading="lazy"
  allow="fullscreen"
  title="日本株 企業関係 3Dネットワーク">
</iframe>
```

### 保有銘柄・選択銘柄を連動させるスニペット（任意拡張）

Muse側で保有銘柄コードや表示中銘柄をURLに付与するだけで連携できる（`postMessage` 実装は不要）。

```html
<iframe
  src="https://asoka501.github.io/Git_stock_networkmap/?embed=1&holdings=7203,6758,8035&focus=7203&hops=1"
  width="100%"
  height="600"
  style="border:0;border-radius:12px;"
  loading="lazy"
  allow="fullscreen"
  title="日本株 企業関係 3Dネットワーク">
</iframe>
```

## 2. URLクエリパラメータ仕様

すべてのパラメータは任意とし、未指定時は安全なデフォルト値で動作する。

| パラメータ | 例 | 動作 |
| --- | --- | --- |
| `embed` | `1` / `true` | 埋め込みスリムUIモードを有効化（ヘッダー最小化、左パネル初期折りたたみ、JSON読込ボタン非表示） |
| `focus` | `7203` | 起動時に指定の証券コードへ自動フォーカス＆詳細パネル表示 |
| `holdings` | `7203,6758,8035` | カンマ区切りの保有銘柄コードを強調リング付きで表示し、保有銘柄フィルタの基準にする |
| `hops` | `1` / `2` | `focus` または `holdings` 指定時に表示する隣接ホップ数（既定：`1`、全上場モード時は過剰描画を防止） |
| `mode` | `core` / `holdings` / `all` | 初期表示スコープ（未指定時：`holdings` があれば `holdings` 周辺、なければ `core` 主要ハブ） |
| `metric` | `marketCap` / `capital` | 初期のノードサイズ基準（既定：`marketCap`） |
| `minValue` | `0` 〜 `90` | 関係値スライダーの初期下限（既定：`0`、大規模データ時は自動調整可） |
| `kind` | `主要顧客,政策保有` | 表示する関係種別の初期絞り込み |
| `rotate` | `0` / `1` | 自動回転の初期ON/OFF（既定：`1`、ただし `focus` 指定時は `0`） |
| `data` | `https://...json` | 任意のネットワークJSON URLを読み込むデバッグ・差し替え用フック（HTTPS限定） |

## 3. スリムUI・快適UX仕様

**原則：「画面の85%以上を3Dキャンバスに開放しつつ、すべての操作機能に1クリックで届く」**

### 3.1 レイアウト比較（通常モード vs `?embed=1` スリムモード）

| UI要素 | 通常モード | スリムモード（`?embed=1`） |
| --- | --- | --- |
| 左上タイトルヘッダー | タイトル＋説明文表示 | **非表示**（スペースを3D描画へ開放） |
| 上部フローティングバー | 検索＋回転＋全体表示＋JSON読込 | **コンパクトなピル型バー**（全社検索・フィルタ開閉・表示範囲切替・全体リセット・全画面） |
| 左コントロールパネル | 画面幅 `md` 以上で常時表示 | **初期折りたたみ**（フィルタボタンで半透明ドロワー開閉） |
| 右詳細インスペクタ | ノードクリック時に表示 | ノードクリック時にスリム幅でスライド表示（画面幅が狭い場合は下部シート風に重なりを回避） |
| JSON読込モーダル | ボタン表示 | 非表示（開発確認が必要な場合はURL通常モードで利用） |

### 3.2 維持する既存機能
- 銘柄名・証券コード・セクターでのインクリメンタル検索
- ノードサイズ基準切替（時価総額 / 資本金）
- 関係値スライダー（弱いエッジの間引き）
- セクター色分け＆凡例クリックによる表示ON/OFF
- ドラッグ回転・ズーム、自動回転ON/OFF、全体表示リセット
- ノードクリックでの関連企業ハイライト・カメラ追従・詳細パネル表示

### 3.3 追加するUX改善機能（Phase 2で実装）
1. **表示スコープ切替（コアハブ / 保有銘柄周辺 / 選択銘柄の1〜2ホップ / セクター別）**
   - 全上場3,800社データでも画面が毛玉にならず、見たい範囲へ瞬時に切り替えられる。
2. **関係種別フィルタ＆出典フィルタ**
   - 「主要顧客・供給」「政策保有株式」「大株主」「提携・協業（LLM）」をチップボタンでON/OFF可能にする。
   - 「定型表のみ / LLM抽出を含む」の切替も用意し、データ信頼度に応じた閲覧を可能にする。
3. **保有銘柄（`holdings`）の視覚的強調**
   - 保有銘柄ノードにゴールドの二重リング／バッジを表示し、「保有銘柄のみ表示」「保有銘柄＋関連企業（1ホップ）」をワンクリック切替。
4. **全画面表示（Fullscreen）ボタン**
   - Muse内の狭いiframeからでも、じっくり分析したいときにワンクリックで全画面拡大できる。
5. **iframe内の操作性配慮**
   - `ResizeObserver` でiframeコンテナのサイズ変化に追従し、リサイズ時の描画崩れを防ぐ。
   - ツールチップがiframe端で見切れないようクランプ位置制御を行う。
   - 銘柄選択後に「さらに1ホップ広げる（この企業の関連を追加展開）」ボタンを詳細パネルへ配置し、芋づる式探索を快適にする。
   - キーボードショートカット（`/` で検索フォーカス、`Esc` で選択解除・パネル閉じ、`R` で全体リセット）。

## 4. 全上場規模（1,600〜3,800社）の高速描画・LOD設計

全ノード・全エッジを一度にWebGLへ流すとフレームレート低下と視認性悪化を招くため、以下の3層で最適化する。

1. **データ読込の段階化（初期表示 0.5秒以内目標）**
   - 起動直後は軽量な `index.json`（全社検索用）と `core.json`（主要ハブ約150〜200社）のみ並列フェッチして即座に描画する。
   - ユーザーがコア外の銘柄を検索・選択したタイミングで `network.json`（全エッジ）と該当 `details/{bucket}.json` をバックグラウンド取得・キャッシュする。
2. **WebGL負荷の動的調整**
   - 表示ノード数が 300 超の場合は `nodeResolution` を下げ（例：`20 -> 10`）、粒子アニメーション（`linkDirectionalParticles`）は選択エッジまたは上位強エッジに限定する。
   - 2Dオーバーレイのロゴ・ラベル描画はカメラ距離によるLODと最大描画件数キャップ（例：画面内近傍上位40件＋選択/ホバー/保有銘柄）を設けて60fpsを維持する。
3. **ロゴ取得のフォールバック強化**
   - 外部ロゴURLが404または未対応の中小型銘柄では、エラー再試行を行わず即座にセクター色＋企業略称イニシャルバッジへフォールバックキャッシュする。
